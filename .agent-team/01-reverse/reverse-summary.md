## Charter A3: 콘텐츠 저장 — 파일 vs CMS vs DB?

### 평가: **발행 시간 관점**에선 세 경로 모두 30분 기준 형식상 충족

- **파일 기반 + 정적 (Netlify):** 발행 오버헤드 ~2분. 마크다운 + git push → 자동 배포.
- **CMS + 정적:** 발행 오버헤드 ~3분. 구조화된 메타데이터 UI → 자동 배포.
- **DB + 동적 (Vercel + PlanetScale):** 발행 오버헤드 ~1분. 폼 제출 → 즉시.

### 단, **진정한 1인 비용은 발행이 아니라 전생명주기**

| 요소 | 파일 기반 | CMS | DB |
|-----|---------|-----|-----|
| 초기 설정 | 1-2일 | 2-4일 | 3-7일 |
| 지속 운영 | 최소 (git) | 최소 (CMS) | 중간 (백업·모니터링) |
| 장애 복구 | git + 파일 백업 | CMS 수출 | DB 복구 계획 |
| 벤더 종속 | 없음 | 있음 | 있음 |
| 총 위험 | **낮음** | 낮음–중간 | 중간 |

### 권고: **파일 기반 + 정적으로 시작**
- 셋업 최단 (1-2일), 운영 최소, 회복력 최대.
- 30편 이후 메타데이터 부담이 병목 되면, **별도 웨이브에서 CMS로 마이그레이션 (전체 재설계 불필요).**

## Charter A5: 앨범 메타데이터 — 수기 vs API?

### 검증 사양

| 서비스 | 라이선스 | 레이트리밋 | 인증 | 강점 | 출처 |
|--------|--------|----------|------|------|------|
| **MusicBrainz** | 비상업용 무료 | 초당 최대 1회 | 읽기 불필요 | 서구 대중음악 | https://musicbrainz.org/doc/MusicBrainz_API |
| **Discogs** | 개인 무료 *(미확인)* | 초당 1회 *(미확인)* | 개인 토큰 | 리이슈, 비닐 *(미확인)* | 웹페치 실패 (HTTP 403) |

**MusicBrainz 커버리지:** 서구 음악에 강함; 비서구·소규모 인디는 약함. *(정량적 % 미확인 — 정성적 평가만 가능)*

### 권고: **하이브리드 (MB 조회 + 수기 폴백)**
- 리뷰 작성 중 **MusicBrainz 조회** 시도 → 데이터 자동 채우기.
- MB에 없으면 **수기 입력** (엣지 케이스).
- 오버헤드: **+2분 (API 적중) ~ +5분 (수기 필요).**
- 1인 효율성: 부분 자동화 + 완전성 보장.

**구현 상 주의:** 조회는 편집 워크플로우에서만 발생. 배포된 사이트에는 API 호출 없음 (아키텍처 영향 없음).

## 4축 아카이브 가능성

**목표:** 독자가 아티스트·연도·장르·레이블로 탐색 (charter §3).

**정적 생성으로 충분:**
- 빌드타임 인덱스 (메타데이터 사전 계산).
- 30편 → ~120 인덱스 항목 → 성능 무시할 수준.
- 클라이언트 검색 필요 없음 (MVP 규모).

**DB 쿼리는 불필요** 사용자 투표, 태그, 알고리즘 같은 동적 기능이 없으면.
