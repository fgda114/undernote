독자 페르소나 (charter §8): **"들을 만한데 아직 안 들은 사람"** — 취향이
없어서가 아니라 닿지 않아서 안 듣는 쪽. Job: "뭘 들을지 고르는 수고 없이,
믿을 만한 사람이 걸러 준 앨범을 듣고, 왜 좋은지 이해하고 싶다."

원 페르소나 (charter §6): 편집장 겸 유일 필자. 개발자가 아니다. Job:
"글 쓰는 일 외의 모든 운영이 내 눈에 안 보이면 좋겠다." SNS 채널(인스타·
유튜브)을 병행 상정 — 사이트는 글 전용 (D8).

## 독자 스토리

### US-1. 리스트에서 근거로 내려가기 `[USP-A · CF-2]`

독자로서, 이 리스트를 믿어도 되는지 확인하기 위해, 올해의 앨범 10선의
각 앨범이 왜 그 순위인지 평론으로 확인하고 싶다.

- **AC1.** Given 확정된 연간 10선 페이지 / When 임의의 항목을 클릭 /
  Then 해당 앨범의 평론 페이지가 열린다. **10개 전 항목에 대해 성립한다** (예외 0).
- **AC2.** Given 10선 페이지 / Then 각 항목에 순위·앨범명·아티스트·점수가
  표시되고, 순위는 점수 내림차순과 일치한다.
- **AC3.** Given 10선 페이지 / Then 원의 서문이 리스트 상단 또는 전단에 있다.

### US-2. 진행 중인 리스트 보기 `[USP-A · CF-3 · D5]`

독자로서, 연말까지 기다리지 않고 지금 뭐가 올해의 후보인지 알기 위해,
현재 노미네이트 현황을 보고 싶다.

- **AC1.** Given 홈 / Then 버킷별 현재 노미네이트(각 0~5개)가 점수순으로
  보이고, 각 항목에서 클릭 1회로 평론에 도달한다.
- **AC2.** Given 어떤 버킷의 평론이 5편 미만인 시점 / Then 그 버킷 보드는
  있는 만큼만 표시된다 (빈 칸을 가짜로 채우지 않는다).
- **AC3.** Given 새 평론의 점수가 기존 보드 5위보다 높음 / When 발행 /
  Then 다음 빌드에서 보드가 교체되어 있다.

### US-3. 점수에 동의 못 할 때 이해의 사다리 오르기 `[USP-B · CF-5]`

독자로서, 내가 듣기엔 별로인데 점수가 높은 이유를 이해하기 위해, 평론에서
그 앨범의 맥락을 다루는 음악 이야기로 이동하고 싶다.

- **AC1.** Given 앨범 X를 참조하는 음악 이야기가 1편 이상 존재 / When X의
  평론 페이지를 열람 / Then "이 앨범이 등장하는 이야기" 목록이 보이고
  클릭 시 해당 글로 이동한다.
- **AC2 (v1.1).** Given X를 직접 참조하는 이야기가 0편 / Then 폴백 사슬
  순서로 표시된다: X의 세부 장르 태그와 교집합이 있는 이야기 → 없으면
  X의 버킷과 일치하는 이야기.
- **AC3.** Given 폴백 대상도 전부 0편 / Then 해당 영역 자체가 표시되지
  않는다 (빈 껍데기 UI 금지).

### US-4. 이야기에서 개별 앨범으로 내려가기 `[USP-B · CF-5]`

독자로서, 계보·장르사 글에서 흥미가 생긴 앨범을 바로 들여다보기 위해,
음악 이야기에 언급된 앨범에서 그 평론으로 이동하고 싶다.

- **AC1.** Given 음악 이야기의 참조 앨범 중 평론이 있는 것 / Then 본문
  또는 참조 목록에서 해당 평론으로 링크된다.
- **AC2.** Given 참조 앨범 중 평론이 없는 것 / Then 링크 없는 텍스트로
  표시된다 (깨진 링크·빈 페이지 생성 금지).

### US-5. 한 달치 결산 받아 보기 `[USP-A · CF-4]`

독자로서, 매일 챙겨 보지 않아도 되도록, 그 달에 다뤄진 앨범을 월말정산
한 페이지로 보고 싶다.

- **AC1.** Given 해당 월에 발행된 평론 ≥1 / Then 그 월의 월말정산 페이지가
  존재하고, 그 달 평론 전체가 점수순으로 나열되며 전 항목이 평론으로 링크된다.
- **AC2.** Given 해당 월 평론 0편 / Then 그 월의 정산 페이지는 생성되지
  않고, 월 목록에도 나타나지 않는다.

### US-6. 지난 글 탐색 `[charter §3 · CF-7]`

독자로서, 관심 장르·아티스트·시기의 글을 찾기 위해, 아카이브를 세 축으로
탐색하고 싶다.

- **AC1.** Given 아카이브 / When 연도·장르(버킷)·아티스트 중 한 축 선택 /
  Then 해당 축의 전체 글이 나열된다 (평론·음악 이야기·아티스트 소개 포함).
  세부 태그가 있는 글은 태그 축으로도 도달 가능하다.
- **AC2.** Given 아카이브 목록 / Then 점수는 표시되지 않는다 (D2 —
  점수 소비는 리스트 지면 전담).
- **AC3.** Given 발행된 모든 글 / Then 최소 한 축 이상에서 도달 가능하다
  (고아 콘텐츠 0 — 빌드 검사 대상).

### US-7. 읽고 나서 바로 듣기 `[charter §2 · CF-10]`

독자로서, 설득된 순간 바로 들어 보기 위해, 평론 페이지에서 그 앨범을
들을 수 있는 곳으로 이동하고 싶다.

- **AC1.** Given 임의의 평론 페이지 / Then 스트리밍 서비스로 나가는 듣기
  링크가 1개 이상 있다.
- **AC2.** Given 자동 생성 링크가 불가한 앨범 / Then 수기 링크로 대체되며,
  둘 다 없으면 빌드가 경고한다 (실패 아님 — 원의 발행을 막지 않는다).

### US-8. 선별 규칙 알기 `[USP-C · CF-8]`

독자로서, "왜 화제작 ○○의 리뷰가 없지?"에 스스로 답하기 위해, 이 매체의
선별 기준을 확인하고 싶다.

- **AC1.** Given 소개/기준 페이지 / Then 다음 세 가지가 명문으로 있다:
  ① 실린 앨범은 "안 들으면 손해" 문턱을 통과한 것뿐이다 ② 다루지 않음 =
  추천하지 않음이다 ③ 점수는 "검증된 것들 사이의 순위"다.
- **AC2.** Given 전체 사이트 어느 페이지 / Then 소개/기준 페이지로 가는
  경로가 전역 내비게이션에 있다.

### US-9. 이 사람이 누군지 알기 `[charter §1 코너3 · CF-6]`

독자로서, 평론에서 처음 본 아티스트를 알기 위해, 아티스트 페이지에서
소개와 관련 글 전체를 보고 싶다.

- **AC1.** Given 글에서 다뤄진 적 있는 아티스트 / When 아티스트명 클릭 /
  Then 그 아티스트의 페이지가 열리고, 소개글(있으면)과 그 아티스트를 다룬
  전체 글(평론·이야기)이 나열된다.
- **AC2.** Given 소개글이 없는 아티스트 / Then 집계 목록만으로 페이지가
  성립한다 (빈 소개 영역을 표시하지 않는다).

## 원(편집자/필자) 스토리

### US-10. 평론 발행 — 글쓰기 외 노동 0 `[USP-A·C · CF-9 · D7]`

필자로서, 글쓰기에만 집중하기 위해, 평론 1편을 낼 때 글과 편집 판단
4가지(앨범·아티스트 / 장르 버킷 / 점수 / 손해 체크) 외에는 아무것도
제공하고 싶지 않다.

- **AC1.** Given 원이 글 + 4항목을 전달 / When User가 발행 파이프라인 실행 /
  Then 원의 추가 개입 없이 평론 페이지·보드 갱신·아카이브 갱신·듣기
  링크·커버·공유 카드가 완성된다.
- **AC2.** Given 4항목 중 누락 (예: 점수 없음) / Then 발행이 진행되지 않고
  무엇이 빠졌는지가 명시된다 (반쪽 발행 금지).
- **AC3.** Given 발매일·레이블 등 앨범 메타데이터 / Then 원에게 요구되지
  않는다 — 시스템 조회(MB) 또는 User 수기가 채운다.
- **AC4.** Given 버킷 목록에 없는 앨범 / Then "그 외"로 발행 가능하다
  (분류 체계가 발행을 막지 않는다).
- **AC5 (v1.1).** Given 세부 장르 태그 미기입 / Then 발행과 전 기능이
  그대로 성립한다 (태그는 옵션 — 부하 0 보장).

### US-11. 음악 이야기 발행 — 연결은 시스템이 `[USP-B · CF-5 · CF-9]`

필자로서, 장르사·계보 글을 쓸 때, 글에 이미 등장하는 앨범 이름과 장르
이름 외에 별도의 링크 작업을 하고 싶지 않다.

- **AC1.** Given 원이 글 + 참조 앨범 목록 전달 / When 발행 / Then 평론이
  있는 참조는 자동 링크되고, 각 참조 앨범의 평론 페이지에 이 글이
  "등장하는 이야기"로 자동 표시된다 (양방향, 원 개입 0).
- **AC2.** Given 이 글 발행 이후 참조 앨범의 평론이 새로 발행됨 /
  Then 다음 빌드에서 링크가 소급 생성된다 (원이 옛 글을 수정할 필요 없음).

### US-12. 점수 고치기·동점 다루기 `[USP-A · D4]`

필자로서, 내 척도의 일관성을 지키기 위해, 발행 후에도 점수를 수정하고
동점을 알림받아 직접 가르고 싶다.

- **AC1.** Given 발행된 평론 / When 점수 수정 (원 → User 전달) / Then 평론·
  보드·진행형 리스트에 반영된다. 단 **확정된 연간 스냅샷은 불변**이다.
- **AC2.** Given 같은 버킷 보드 5위권 내 동점 발생 / Then 빌드가 원에게
  전달할 알림을 남기고, 기본 정렬은 평론 발행일 이른 순으로 처리된다
  (원의 조정은 선택, 강제 아님).

### US-13. 연말 확정 — 서문 한 편으로 `[USP-A · CF-2 · D5]`

편집장으로서, 한 해를 결산하기 위해, 서문 한 편을 쓰는 것만으로 진행형
보드를 "올해의 앨범" 확정 리스트로 전환하고 싶다.

- **AC1.** Given 원이 확정 선언 + 서문 전달 / When 확정 실행 / Then 그
  시점의 10선·버킷별 선정·노미네이트가 스냅샷으로 동결되고 확정 지면이
  공개되며, 이듬해 보드는 빈 상태로 시작한다.
- **AC2.** Given 확정 이후 지난해 발매 앨범의 평론 발행 / Then 확정
  리스트는 변하지 않고, 해당 평론은 아카이브에만 편입된다.
- **AC3.** Given 연말 시점 평론 2편 이하인 버킷 / Then 그 버킷 리스트는
  그 해 발행되지 않는다 (D1 성립 규칙 — 원이 규칙 변경을 원하면 설정으로).

### US-14. 아티스트 소개 발행 `[charter §1 코너3 · CF-6 · CF-9]`

필자로서, 세 번째 코너를 채우기 위해, 아티스트 소개글을 글 + 아티스트명만으로
발행하고 싶다.

- **AC1.** Given 원이 글 + 아티스트명 전달 / When 발행 / Then 해당 아티스트
  페이지의 소개 영역에 글이 실리고, 기존 집계 목록과 결합된다.
- **AC2.** Given 그 아티스트를 다룬 평론·이야기 / Then 소개글 발행 전후와
  무관하게 자동 집계된다 (순서 의존성 없음).

### US-15. SNS에 공유하기 — 링크 하나로 `[CF-11 · D8]` (v1.1 신규)

운영자로서, 내 인스타·유튜브 채널에서 사이트로 유입을 만들기 위해, 글
링크를 붙여넣는 것만으로 제대로 된 공유 카드가 보이길 원한다.

- **AC1.** Given 임의의 공개 페이지 URL / When SNS·메신저에 붙여넣기 /
  Then 유형별 템플릿의 카드(제목·설명·이미지)가 표시된다 — 원의 추가
  작업 0.
- **AC2.** Given 평론 페이지의 카드 / Then 커버·앨범·아티스트·매체명이
  있고 **점수는 없다** (D2 — 점수를 피드의 간판으로 만들지 않는다).
- **AC3.** Given 커버 없는 앨범의 평론 / Then 텍스트 기본형 카드로
  폴백된다 (깨진 이미지 금지).

## INVEST 자기 점검

- **Independent:** US-3/4(사다리)는 US-10/11의 데이터에 의존하나 각각 독립
  구현·검증 가능. 에픽 순서(core-features §4)가 의존을 흡수한다.
- **Negotiable:** D1(버킷 구성)·D4(노미네이트 방식)·Q3(월간 성격)는 원
  결정에 따라 AC의 상수만 바뀐다 — 스토리 구조는 유지.
- **Valuable:** 전 스토리가 USP 또는 charter 조항·원 확정 답변으로
  역추적된다 (각 제목의 출처 표기).
- **Estimable/Small:** 각 스토리는 정적 생성 규칙 1~2개 규모. James의
  build-plan 분해에 적합.
- **Testable:** 전 AC가 빌드 산출물 검사 또는 페이지 상태 검사로 반증 가능.
  Matthias(QA)가 수동 확인 가능한 수준으로 씀.
