## 3. Findings

### M-1. E-202(커버 미확보) **경고가 미구현** — major

- **재현:** 커버 필드 없는 앨범 6종 투입 → 빌드 성공 · 플레이스홀더 렌더 ✅ · OG 기본형 폴백 ✅ — 그러나 `reports/build-report.md`의 경고 섹션 = **"없음."**
- **깨진 AC:** SS-14 인수조건 "발행은 성공 + **경고** + 플레이스홀더" / 스토리 w5-1 AC11 "발행 성공 + **E-202 경고** + 플레이스홀더" — 경고 절반 미충족. exceptions.md E-2xx 계약(빌드 진행 + build-report 기재)의 E-202 행이 비어 있다.
- **증거:** `grep -rn "E-202" src/` → 방출 지점 0 (주석 2곳뿐). `tests/unit/checker.test.ts:22`는 "E-202가 실패가 **아니다**"만 검사 — 경고 존재를 검사하는 테스트가 없어 이 누락이 초록으로 통과해 왔다.
- **기대 vs 실제:** 기대 = 커버 없는 앨범마다 build-report 경고 1행 (User가 커버 확보 작업을 인지하는 유일한 통로 — D7상 커버는 원이 아니라 시스템+User 몫이므로 이 통지가 실질 기능이다). 실제 = 무통지, 지면을 눈으로 봐야만 인지 가능.
- **왜 blocker가 아닌가:** 독자 도달 산출물은 전부 정상 (플레이스홀더·폴백 카드). 결손은 편집자 보고선 1개다.
- **수정:** checker pre-pass에서 `album.cover` 부재 시 warning 1건 방출 + "경고가 실제로 실린다"를 검사하는 픽스처 테스트 1개 (E-201과 같은 패턴 — 소규모).

### m-1. E-205가 실질 도달 불능 경로 — minor (기록)

자동 검색형 듣기 링크는 앨범명·아티스트명만으로 항상 구성 가능하므로 "자동·수기 모두 부재"(E-205 조건)가 실제로 발생하지 않는다. US-7 AC1은 오히려 상시 충족되므로 실해 0 — 단위 테스트는 존재. 사양의 보수적 이중화로 이해하고 기록만 남긴다.

### m-2. 실기기 확인 3건 미완 — minor (launch-gate 문서가 이미 잔여로 관리 중)

키보드 통독·다크 모드·360px 가로 스크롤은 구조 검증(JS 0·전부 앵커·prefers-* 토큰·max-width)까지 완료, **실기기 확인은 미실시** (나의 검증도 HTML/CSS 구조 수준 — 헤드리스 브라우저 실측은 이 환경에서 미수행). 공개 전 launch-gate §5 체크리스트대로 1회 필요.

### 잔여 리스크 (결함 아님)

- **R-a. album-add 실 MB API 스모크 미실시** — 목 픽스처 테스트 10건 통과 (1req/s 간격·UA·E-401~404 폴백·산출 YAML의 스키마 통과까지). 실 API 왕복은 테스트 전략 문서대로 "수동 스모크만"이며 내 세션에서는 레이트리밋 존중으로 미수행 — **User 첫 실사용(원의 첫 앨범 등록) 전 1회 스모크 권고.**
- **R-b. 검증 시점과 HEAD의 시차** — 게이트·US 실측 대부분은 재개분 직전 사본 기준이고, HEAD(재개분 4커밋: early_stage_threshold 설정화·goatcounter 옵트인 스니펫·픽스처 배포 게이트)는 테스트 130/130 + 결정성 재실측으로 재확인했다. goatcounter 스니펫은 미설정 시 스크립트 0 (JS 0 유지 — 코드 확인).

## 4. 공개 게이트 권고 — **통과 (조건부 아님 · 권고 사항 3건 동반)**

- **blocker 0.** US-1~15 전수 통과 — 인수조건이 깨진 곳은 M-1(경고 보고선 1개)뿐이고 독자 도달 산출물은 전 상태에서 정상이다. USP-A(E-110)·USP-B(소급 링크)·USP-C(E-106)가 전부 **깨뜨린 빌드로 실증**됐고, 결정성은 두 상태에서 각 2회 빌드 해시 동일로 실측됐다.
- 동반 권고: ① **M-1은 공개와 무관하게 조기 수정** (몇 줄 규모 — Andrew 대기 중이면 지금) ② 실기기 3건은 launch-gate §5 잔여대로 공개 전 1회 ③ 원의 첫 실앨범 등록 전 album-add 실 API 스모크 1회.
- 이 문서 밖 절차(픽스처 제거→실콘텐츠 투입·GitHub Pages 활성화·성능 예산 결정)는 launch-gate §5가 이미 관리한다 — 픽스처 잔존 배포는 재개분 CI 게이트가 기계적으로 차단함을 확인했다.
