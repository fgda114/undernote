### N-1. W5.2 AC3 ↔ 작업 1의 E-301 범위 자기모순 (상류 모순의 무해석 전사)

- **위치:** `story-w5-2` AC3 vs 작업 1 4번째 항목.
- AC3은 "동점 두 앨범 → E-301 생성"(SS-3 인수조건 전사 — 무제한), 작업 1은 "경계 동점 감지(5↔6·10↔11·1↔2)"(R-1·E-301 정의 — 한정). 상류 자체가 갈라져 있고(SS-3·US-12 AC2 광의 vs exceptions 협의) 스토리가 해소 없이 양쪽을 실었다. **시나리오:** Andrew는 작업 1대로 협의 구현 → AC3 문언 테스트(비경계 동점) 실패, 또는 광의 구현 → SSOT(exceptions) 위반. Matthias의 AC 판독과도 갈린다.
- **수리:** 규범 = exceptions(E-301은 경계 동점 한정)로 명시하고, AC3 픽스처를 경계(5↔6)에 구성 + "비경계 동점 → E-301 미산출" 반례 케이스 추가.

### N-2. 검증 이원성 미해소 — Astro Zod(V1) vs checker의 E-100~109 소유 + B-1 전량 보고

- **위치:** `story-w5-0` AC2 · `story-w5-1` 작업 1·AC6·파일 구조(`src/lib/checker/ # E-100~109`).
- 상류 셋이 긴장 관계다: architecture-overview V1 = "Astro Content Collections + Zod", code-structure = "content.config.ts가 §3의 **유일한 구현체**" + "lib는 Astro import 금지", B-1 = "실패 전부 모아 한 번에 + 한국어 + 수정 방법". Astro 내장 검증은 fail-fast·프레임워크 서식이라 B-1·W5.0 AC2를 그대로는 못 채우고, checker에 스키마를 재구현하면 "유일한 구현체" 위반 + 이중 정의 드리프트가 시작된다. checker는 레이어 규칙상 content.config.ts를 import할 수도 없다. **시나리오:** Andrew가 content.config.ts에 Zod를 다 짠 뒤 W5.1 AC6에서 벽에 부딪혀 병렬 검증기를 급조 → 두 검증기의 의미가 갈라진다.

### N-7. 빌드 시계 잔여 스위프 결과 2건 (지시대로 전 지면 훑음)

- **ⓐ Footer © 연도:** ui-spec §1.1 푸터에 "©"만 있고 내용 미정 — Andrew의 근육 기억은 `new Date().getFullYear()`다. R-10("빌드 시각의 유일한 소비처 = 종료 월 판정") 위반이며, 같은 날 2회 빌드 해시 게이트로는 **잡히지 않는** 잠복 누수다. 수리: 저장소 유래 값(`active_year` 또는 고정 문자열)으로 명시.
- **ⓑ 해시 게이트 범위:** BuildReport의 `built_at`(§4.6 required)은 본질적 비결정 값. `reports/`는 dist 밖이라 설계상 무해하지만, W5.0 AC4의 "산출 해시" 범위가 미정의라 Andrew가 reports/를 포함하면 게이트가 상시 오탐한다. 수리: "해시 범위 = `dist/` 한정"을 W5.0에 한 줄 명시.
- 그 외는 깨끗함을 확인: 보드 캡션(스토리가 이미 차단), 월말 캡션·확정 캡션·극초기 배너 전부 저장소 유래.

### N-8. mode=tag 리드 카피 미정의 + 폴백 표시 편수 상한 누락

- **위치:** `story-w5-4` AC8 · api-contracts §4.5(mode 4종) vs ui-spec §2.6(카피 2종).
- Backlinks mode는 direct|tag|bucket|none 4종인데 리드 카피는 직접·장르 폴백 2종만 정의됨 — mode=tag일 때 Andrew가 카피를 지어내야 한다("이 장르가 낯설다면 — {버킷}"은 태그 매칭 결과에 부정확). 또 components §11의 폴백 "1~2편" 상한이 스토리에 안 실렸다(태그 일치 5편이면 전부? 2편?). **수리:** tag 모드 카피 1줄 확정(Jonnathan 마이크로 결정 또는 직접 참조 카피 재사용 명시) + 폴백 상한(direct=전부, tag/bucket=최대 2) 명시.

### N-9. 파비콘/터치 아이콘 미배정

- **위치:** design-handoff §3(SVG 1 + PNG 180px — seal 도트 모티프) — 어느 스토리의 작업·파일 목록에도 없음. **수리:** W5.1 작업 3(디자인 기반)에 1줄 추가.

### N-10. 극초기 임계값의 site.yaml 계약 확장이 스토리 중간 협상으로 남음

- **위치:** `story-w5-2` 파일 구조 주석. 스토리가 문제를 정직하게 인지·경로 명시한 점은 좋으나(§7 가산 규칙 + 리드 보고), 이런 계약 확장은 W3에서 선결됐어야 할 성질이다 — 지금 리드·James가 §3.8에 옵션 필드 1개(예: `early_home_threshold`)를 선승인해 두면 Andrew의 중단 지점이 사라진다.
