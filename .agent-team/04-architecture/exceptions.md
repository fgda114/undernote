## 1부 — 결정성 규칙 R-1 ~ R-10

### R-1. 전체 순서 (동점 처리 — D4·SS-3)

모든 점수 정렬(보드·10선·월말정산·스냅샷 생성)은 다음 3키로 **전순서**를 만든다:

```
1차: score        내림차순
2차: review.date  오름차순  (발행일 이른 쪽 우선 — "더 오래 검증대에 있었던 쪽", Joshua D4)
3차: album slug   사전순 오름차순
```

- **3차 키는 아키텍처 추가다** (Joshua는 2키까지 정의). 같은 날 발행된 동점
  2편이 빌드마다 순서가 뒤집히는 비결정성을 막는다. slug는 불변(R-9)이므로
  안전한 최종 타이브레이커다.
- 경계 동점(보드 5↔6위, 10선 10↔11위, 버킷 1↔2위)은 규칙대로 처리하되
  **E-301 알림**을 남긴다 — 원이 소수점 조정으로 직접 가를 기회 (강제 아님).
- 문자열 비교는 코드포인트 기준 고정 (로케일 collation 사용 금지 — 환경 의존).

### R-2. 사후 점수 수정의 전파 범위 (SS-3·6)

| 대상 | 점수 수정 시 |
|---|---|
| 평론 페이지 · 아카이브 · 아티스트 집계 | **반영** (매 빌드 재도출) |
| 진행형 보드 · 진행형 10선 | **반영** — 경계 변동 시 진입·탈락 자동 (배지 포함) |
| 과거 월말정산 | **반영** (R-5 — 월말정산은 스냅샷이 아니다) |
| **확정 연간 스냅샷** | **불변.** 어떤 수정·추가 평론에도 (리스트 = 발표 시점의 선언) |

### R-3. 연도·월 귀속 (리드 확인 요청 항목 — 해소)

**두 개의 귀속 축이 의도적으로 공존한다.** SS-11의 "발행 기준"은 SS-5의
"발매 기준"과 모순이 아니라 다른 지면의 다른 질문이다:

| 지면 | 귀속 키 | 질문 | 근거 |
|---|---|---|---|
| 연간 리스트 (보드·10선·스냅샷) | **발매 연도** | "올해 *나온* 앨범 중 최고는" | D3 · SS-5 (charter §1: 올해 나온 것을 다뤄야 올해의 리스트) |
| 아카이브 연도 축 | **발행 연도** | "이 매거진이 올해 *쓴* 글은" | SS-11 |
| 월말정산 | **발행 월** | "이 매거진의 이번 달 결산은" (구반 평론 포함) | SS-7 |

- 따라서 "2025년 발매 앨범의 2026년 평론"은: 2026 리스트 후보 ❌ ·
  2026 아카이브 ✅ · 발행월 정산 ✅. 이것이 사양이다.
- 확정 후 발행된 지난해 발매작 평론은 스냅샷에 소급되지 않는다 (§5 요구 7).

### R-4. 빈 집합의 취급 — "가짜로 채우지도, 사과하지도 않는다"

| 상황 | 처리 |
|---|---|
| 버킷 평론 5편 미만 | 있는 만큼만 표시 (빈 칸 placeholder 금지 — US-2 AC2) |
| 그 월 평론 0편 | 정산 페이지·목록 항목 미생성 (SS-7) |
| 역링크 폴백 전부 0편 | 영역 자체 미표시 (US-3 AC3) |
| 소개글 없는 아티스트 | 집계만으로 페이지 성립, 빈 소개 영역 미표시 (US-9 AC2) |
| 평론 0~5편 극초기 홈 | 보드 축소 + 최신 평론이 얼굴 (D5 — Jonnathan 빈 상태 시안) |

### R-5. 월말정산은 살아 있는 도출물이다

SS-3이 명시한 대로 점수 수정은 과거 월 정산에도 반영된다. 확정(불변) 지면은
연간 스냅샷 **하나뿐**이다. 월말정산을 스냅샷화하지 않는 이유: 불변 지면이
늘수록 "점수 수정 → 어디는 바뀌고 어디는 안 바뀜"의 규칙이 복잡해진다.
불변의 예외는 한 곳으로 몰아둔다.

### R-6. 10선이 10개 미만인 해

그해 발매작 평론이 10편 미만이면 있는 만큼 동결한다. 순위를 가짜로 채우지
않는다 (R-4와 동일 원칙). 지면 표기 확정 (Jonnathan, ui-spec §4.2 · 2026-09-01):
제목은 "{연도} 올해의 앨범"으로 고정(개수 하드코딩 금지), 개수는 캡션
"{n}장의 앨범"으로 자동 표기. "10선"은 내부 용어로만 쓴다.

### R-7. "그 외"(etc) 버킷의 전 지면 취급

| 지면 | etc 앨범 |
|---|---|
| 장르 보드 | **제외** (SS-4) |
| 연간 10선 | **포함** (D3 — 버킷 밖 걸작의 누락 차단) |
| 월말정산 | 포함 (발행월 귀속이므로 버킷 무관) |
| 아카이브 버킷 축 | "그 외" 그룹으로 포함 |
| 노미네이트 배지 | 없음 (보드 대상이 아니므로 — 정의상) |

### R-8. 버킷 설정의 연도 결속 (D1 — "과거 연도 고정"의 실체)

- 앨범의 버킷 유효성은 **발매 연도의 설정 블록** 기준: `bucket ∈ genres.yaml[발매연도].buckets ∪ {etc}` (위반 = E-104).
- 발매 연도의 설정 블록이 없는 구반 앨범: 전 연도 블록의 합집합 ∪ {etc}로
  검증 (아카이브 그룹핑용일 뿐 — 리스트 무관).
- 과거 연도의 리스트 지면은 **스냅샷에서만** 렌더된다. 스냅샷은 버킷
  label까지 동결 저장하므로, 이듬해 원이 버킷을 바꿔도(새 연도 블록 추가)
  과거 지면은 영향 0. **설정 변경으로 과거가 바뀌는 경로가 구조적으로 없다.**
- 과거 연도 설정 블록 수정 금지 (운영 수칙 — git 이력으로 감사).

### R-9. slug·URL 불변

발행된 콘텐츠의 slug(=URL)는 바꾸지 않는다. 공유 카드(D8)로 유통된 링크가
죽으면 유입 축 ②가 끊긴다. 오타 등 불가피한 변경은 호스팅 리다이렉트 규칙
추가와 함께 (운영 수칙 — W5 문서화).

### R-10. 시계·시간대 고정

- 월말정산의 "종료된 월" 판정과 모든 날짜 귀속은 **Asia/Seoul 고정**이다.
  CI가 UTC로 돌아도 결과가 같아야 한다 (구현: 빌드 설정에 TZ 명시).
- 빌드 시각은 "종료된 월" 판정에만 쓰인다. 그 외 도출은 시계 무관 —
  같은 저장소 = 같은 사이트가 유지된다 (스냅샷 `finalized_at`은 finalize
  시점 기록일 뿐 도출 입력이 아니다).

## 3부 — 장애·부분 실패 설계

| 장애 | 영향 | 설계 응답 |
|---|---|---|
| MusicBrainz·CAA 다운 | 편집 시점 조회만 | 수기 폴백이 1급 경로 (E-401~404). **배포된 사이트 영향 0** — 외부 의존이 빌드·런타임에 없다 |
| 호스팅 CDN 장애 | 사이트 열람 불가 | 정적 산출물이라 어느 정적 호스트로든 즉시 재배포 가능 (벤더 종속 0 — ADR-0009). 감내 판단: 개인 매거진에 멀티 CDN은 과잉 |
| 빌드 실패 방치 | 신규 글 미배포, **기존 사이트는 마지막 성공 상태로 계속 서빙** | 정적 호스팅의 기본 속성 — 실패가 독자에게 보이지 않는다. User에게만 보인다 |
| 스트리밍 검색 URL 패턴 변경 | 아웃링크 열화 | 수기 오버라이드로 즉시 복구 가능. 패턴은 설정 파일 (코드 수정 불요) |
| npm 공급망 | 빌드 오염 | lockfile 고정 + 의존 최소 (관측·대응은 W5 운영 수칙) |

**재시도·서킷브레이커·큐가 없는 이유 (명시적 판단):** 원격 호출이 존재하는
유일한 지점(편집 도구)에 사람이 앉아 있다. 자동 복원 기제는 무인 시스템의
도구다 — 여기 넣으면 복잡성만 산다. 실패는 보고하고 사람이 폴백한다.
