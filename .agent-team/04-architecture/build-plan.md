## 1. 인력 구성 판단 — **W5는 1명으로 운영할 것을 권고한다**

**권고: Andrew(프론트) 단독 구현. Phillip 미스폰.**

근거 — 이것은 인력 아끼기가 아니라 구조의 귀결이다:

1. **백엔드가 없다.** 런타임 서버·DB·API가 0이므로 Phillip의 전통적 영역
   (서버, 스키마 마이그레이션, 인프라 운영)이 존재하지 않는다. 남는 "데이터
   작업"은 빌드 스크립트 수백 줄(derive·checker·album-add·finalize)이며,
   이는 사이트 코드와 **같은 npm 프로젝트, 같은 언어(TS), 같은 테스트
   러너** 안에 있다.
2. **억지로 나누면 교집합이 생긴다.** Astro 프로젝트에서 콘텐츠 스키마
   (`src/content.config.ts`)는 derive의 입력이자 페이지의 입력이다. 2명이
   나누면 이 파일과 `package.json`·CI 설정이 공유 지대가 된다 — "교집합 0"
   요건을 지키려고 인위적 인터페이스를 만들면 1인이면 없었을 조율 비용이
   생긴다 (분산 모놀리스의 팀 버전).
3. **규모.** 콘텐츠 파일 수백 개·페이지 유형 ~10종·파생 로직 9패턴
   (`data-model-erd.md` §3). 1인 + AI 보조로 충분히 끓일 수 있는 호수다.
4. **Andrew인 이유:** 작업량의 중심이 Jonnathan 시안의 충실한 구현(페이지
   유형 10종 · 긴 글 읽기 경험 · 카드 템플릿)이고, 파생 로직은 이 폴더에
   이미 알고리즘 수준으로 사양화되어 있다 (`service-sequences.md` B-2~B-9 ·
   `exceptions.md` R-1~R-10 — 구현은 번역 작업).

**폴백 — 리드가 2명을 유지한다면 (차선):** 교집합 0을 지키는 유일한 절단선:

| 담당 | 소유 경로 | 내용 |
|---|---|---|
| Phillip | `scripts/**` · `src/lib/**` · `tests/**` · `src/content.config.ts` | 파이프라인: 스키마(Zod)·derive·checker·album-add·finalize + 전 테스트 |
| Andrew | `src/pages/**` · `src/components/**` · `src/layouts/**` · `src/styles/**` · `public/**` | 지면: 페이지 유형 전부 + OG 카드 시각 템플릿 |
| 공유 금지 지대 | `package.json`·CI 설정 — **Phillip 단독 소유**로 지정 (변경 요청은 메시지로) | |

인터페이스 = `api-contracts.md` §4 (도출 데이터 구조). Andrew는 이 구조를
가공 없이 렌더한다 (P1 패턴 — 판단 로직의 템플릿 침투 금지). 이 계약이
있으므로 병렬 작업이 가능하지만, **권고는 여전히 1인이다.**

## 2. 단계 계획 (에픽 E1~E5 → 구현 단계)

순서는 Joshua §4의 의존 관계를 따른다. 규모 표기는 상대치(S<M<L)다 —
베이스라인 없는 시간 수치는 적지 않는다. 각 단계의 DoD는 해당 SS 인수조건
전부 + 명시된 E-* 구현이다.

### W5.0 — 셋업 (S)
- 저장소 스캐폴드: `code-structure.md`의 트리 그대로. Astro 5 (ADR-0002 —
  **User 확인 후** 착수. 거부 시 ADR 대안 경로).
- 호스팅 선택: ADR-0009 후보 3종의 **무료 한도 실확인** 후 1개 확정 + git
  연동 자동 빌드. TZ=Asia/Seoul 명시 (R-10).
- CI: push → 검증·테스트·빌드. 실패 시 배포 없음 (기존 사이트는 마지막
  성공 상태 유지 — `exceptions.md` 3부).
- **DoD:** 빈 콘텐츠로 빌드·배포 성공 + 의도적 스키마 위반 픽스처가 빌드를
  실패시킴 (파이프라인의 존재 증명).

### W5.1 — E1: 평론 + 발행 파이프라인 (L — 최대 단계)
- 콘텐츠 스키마 전부 (`api-contracts.md` §3 → Zod). E-100~E-109 검증.
- `album-add` CLI: MB 조회(1req/s·UA 헤더) + CAA 커버(축소 저장·출처 기록 —
  ADR-0008 5원칙) + 수기 폴백 대화 흐름 (E-401~404).
- 평론 페이지 (CF-1): 히어로(점수 없음)·본문·말미 점수 블록(D2)·듣기
  링크(SS-13 패턴+오버라이드)·커버(플레이스홀더 폴백).
- OG 메타 + 카드 생성 (SS-15 · ADR-0010 satori). **카드 전 유형 점수 비표시(E-115)**.
  `og_use_cover` 킬스위치 동작. 템플릿 구현 순서: 기본형 → 리스트형 → 평론형
  (커버 합성 — ADR-0008 결론 후 활성화. Jonnathan handoff 합의 · 전 유형 기본형 폴백 성립).
- **DoD:** SS-1·2·13·14·15 인수조건 전부 + US-10 AC1~5. 픽스처 평론 1편이
  발행 파이프라인 전체를 통과해 카드까지 완성.

### W5.2 — E2: 리스트 엔진 + 홈 (M)
- derive: R-1 3키 정렬(십분위 정수 연산 — ADR-0004) → 보드(SS-4) → 진행형
  10선(SS-5) → 월말정산(SS-7, 종료 월 판정 R-10).
- checker: 링크율 100%(E-110)·고아(E-113)·내부 링크(E-112)·OG 전수(E-111)·
  동점 알림(E-301)·build-report 산출.
- `finalize` CLI: 스냅샷 생성 + activeYear 전환 (SS-6 · E-405 · R-2).
- 홈: 보드 현황판 + 최신 평론, 빈 상태(0~5편) 포함 (D5 — Jonnathan 시안).
- **결정성 게이트 (이 단계의 핵심 테스트):** 동일 픽스처 2회 빌드 → 산출
  HTML 해시 동일. 동점·경계·연도 귀속 픽스처(R-1·R-3·R-7 각 1개 이상)의
  골든 파일 테스트.
- **DoD:** SS-3~8 인수조건 전부 + US-1·2·12·13 AC.

### W5.3 — E3: 탐색 (S)
- 아카이브 4축 인덱스(SS-11, 점수 비표시) + 아티스트 페이지(SS-12).
- **DoD:** SS-11·12 + US-6·9·14 AC. 고아 검사가 실동작(글 하나를 의도적으로
  고아로 만들어 빌드 실패 확인).

### W5.4 — E4: 사다리 (S)
- 이야기 페이지 + 참조 해석(SS-9) + 역링크 폴백 사슬(SS-10 — 섞지 않음,
  최초 비지 않는 단계만).
- **DoD:** SS-9·10 + US-3·4·11 AC. 소급 링크 테스트(평론 추가 → 재빌드 →
  링크 생성).
- 계보 시각화는 **이 단계에 없다** — Jonnathan 시안 → 원 선택 → 실측 후
  별도 판단 (usp.md §2 저비용 한정).

### W5.5 — E5: 정체성 지면 + 공개 게이트 (S)
- 소개/기준 지면 (CF-8 — 카피는 원+리드, US-8 AC 3문장 필수).
- 공개 전 점검: Matthias(QA)의 US-1~15 AC 전수 수동 확인 + 페이지 초기 전송 예산(HTML+CSS+폰트 < 500KB — architecture-overview §4와 동일 기준, 초과 시 조정 협의) + 계측 도구 확정(관측 요구:
  평론↔이야기 이동률 측정 가능).
- **DoD:** E1+E2+E5 완성 = 최소 공개 단위 (Joshua 릴리스 판단). E3·E4는
  공개 후 순차 가능.

## 4. 운영 수칙 (W5 산출 문서 `09-docs`로 승계할 항목)

1. 저장소·호스팅 계정 2FA (위협 모델의 실질 전부 — overview §7).
2. 스냅샷 수동 편집 금지 — 잘못된 확정은 삭제 후 finalize 재실행.
3. 과거 연도 버킷 설정 수정 금지 (R-8). slug 변경 금지, 불가피 시
   리다이렉트 동반 (R-9).
4. 발행 1건 = 원자 커밋 (앨범+평론+커버 함께 — 부분 발행 금지의 커밋 규약).
5. build-report의 E-3xx 알림은 User가 원에게 전달 (동점 조정·확정 시점).
