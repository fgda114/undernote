# ADR-0004. 점수 표현 = 문자열 저장 + 정수 십분위 연산

| | |
|---|---|
| 상태 | **Accepted** |
| 작성 | James · 2026-09-01 |
| 의존 | charter §5 (0.0~10.0 소수 1자리) · D2 · SS-3 |

## 맥락

점수는 이 제품의 유일한 정렬 축이다. 리스트 순위·보드 진입/탈락·10선이 전부
점수 비교에서 나오므로, **비교 연산이 1비트도 흔들리면 안 된다.**
YAML/JS의 부동소수점(`8.3` → IEEE754 근사값)은 등호 비교·정렬에서 신뢰 불가.

## 결정

1. **저장(프론트매터): 문자열** — `score: "8.3"`. 검증 정규식 `^(10\.0|[0-9]\.[0-9])$` (SS-1 스키마 레벨).
2. **연산(파생 로직): 정수 십분위** — 로드 시 `scoreTenths = 83`으로 변환, 모든 비교·정렬·동점 판정은 정수로만 수행.
3. **표시: 저장 문자열 그대로** — 포맷 변환 없음, "8.30"·"8" 같은 표기 변형이 원천 차단된다.

## 대안

1. **float 저장·연산** — `8.3*10 !== 83` 류의 근사 오차가 동점 판정을 오염. 기각.
2. **정수(83) 직접 저장** — 원·User의 전사 오류 위험(8.3을 83으로 옮겨 적는 인간 인터페이스가 나쁨). D7(원의 접점) 관점에서 기각.

## 결과

- (+) 동점 판정·정렬이 완전 결정적 (exceptions.md §결정성).
- (−) 로드 시 파싱 1단계 추가 — `src/lib/score.ts` 한 곳에 격리.
