# ADR-0003. 앨범을 독립 엔터티로 분리한다

| | |
|---|---|
| 상태 | **Accepted** |
| 작성 | James · 2026-09-01 |
| 의존 | ADR-0001 · Joshua §5.1 |

## 맥락

앨범 메타데이터(발매일·아티스트·버킷·태그·커버·듣기 링크)를 어디에 두는가.
소비자는 셋: 평론(1:1), 음악 이야기(N:M 참조), 리스트 도출(발매 연도·버킷·점수).

## 결정

**앨범을 `content/albums/{album-id}.yaml` 독립 데이터 파일로 두고, 평론·이야기는 `album-id`로 참조한다.**

- 음악 이야기는 **평론 없는 앨범**도 참조한다(SS-9: 링크 없는 텍스트 표시). 평론 프론트매터에 앨범을 내장하면 이 앨범들이 표현 불가.
- 평론이 나중에 발행되면 소급 링크(SS-9)가 성립하려면 "같은 앨범"의 동일성 판별 키가 필요 — 파일명 문자열 매칭이 아니라 ID 참조가 답이다.
- 평론:앨범 = **1:1 강제** (앨범당 평론 1편 — 중복 시 빌드 실패 E-105). "다룸 = 추천"(USP-C)과 리스트 도출의 유일성 전제.

## 대안

1. **평론 프론트매터에 앨범 내장** — 평론 없는 참조 앨범 표현 불가, 이야기의 참조가 자유 문자열이 되어 오타가 침묵 통과. 기각.
2. **단일 albums.yaml 전체 목록 파일** — git 충돌·병합 단위가 나빠지고 1파일 1사실 원칙 훼손. 기각.

## 결과

- (+) SS-2(메타 해석)·SS-9(참조 해석)·SS-13(듣기 링크)이 한 엔터티에 수렴.
- (−) 발행 시 파일이 2개(앨범 + 평론) 생긴다 — 스캐폴드 스크립트(CF-9)가 함께 생성하므로 사람 비용 0.
