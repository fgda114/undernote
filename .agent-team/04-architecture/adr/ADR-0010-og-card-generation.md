# ADR-0010. 공유 카드 = 빌드 타임 이미지 생성 (satori + resvg)

| | |
|---|---|
| 상태 | **Accepted** |
| 작성 | James · 2026-09-01 |
| 의존 | SS-15 · CF-11 · D8 · ADR-0008 §5 · Jonnathan 요구 1 (2026-09-01 합의) |

## 맥락

유입 축의 실체가 "링크를 붙여넣었을 때 제대로 보이는 카드"다 (D8). 정적 사이트이므로
카드 이미지도 빌드 산출물이어야 한다. 원 노동 0, 페이지 유형별 템플릿 (SS-15).

## 결정

1. **매 빌드, 전 공개 페이지에 1200x630 PNG 카드 1장 생성** — satori(HTML/CSS→SVG) + @resvg/resvg-js(SVG→PNG). 셀프호스팅 서브셋 폰트(Jonnathan 요구 2) 재사용.
2. **템플릿 3종:** 평론(합성 카드 — 축소 커버+앨범·아티스트·매체명) / 리스트(보드·10선·월말정산 — 순위·앨범·아티스트) / 기본형(제목+매체명 — 이야기·아티스트·기타 + 커버 부재·법적 전환 시 폴백). **전 유형 점수 비표시** (ui-spec §11 확정 2026-09-01) — 빌드 검증 E-115로 강제.
   구현 순서(Jonnathan handoff 합의): **기본형 → 리스트형 → 평론형.** 평론형(커버 합성)은 ADR-0008 §5 결론 전까지 비활성 가능 — 전 유형이 기본형 폴백으로 성립하므로 차단 없음.
3. OG 메타 3요소(title·description·image)는 페이지 템플릿에서 항상 출력, 검증은 E-111(OG 3요소 부재 = 실패) · E-115(카드·메타 점수 노출 = 실패, 전 유형).

## 대안

1. **커버 원본을 og:image로 직접 지정** — 카드 단독 유통 맥락에서 ADR-0008 §5 위반 소지 + 크기 비율 부적합. 기각.
2. **정적 공용 이미지 1장** — 원 노동 0은 같으나 "리스트 성격이 드러나는 카드"(SS-15) 미충족, 유입 축 가치 포기. 기각.
3. **sharp 합성만으로 구현** — 텍스트 레이아웃(한글 줄바꿈·말줄임)을 수동 구현하게 됨. satori가 이 일을 위해 존재. 기각.

## 결과

- (+) 원은 링크만 붙여넣으면 된다 (D8 접점 0).
- (−) 빌드 시간 페이지당 이미지 1장 추가 — 수백 페이지 규모 예산(<60초, ADR-0002) 내로 관리, 초과 실측 시 변경분만 생성하는 캐시 도입.
