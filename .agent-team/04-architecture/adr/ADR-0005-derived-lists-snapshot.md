# ADR-0005. 리스트는 저장하지 않는다 — 빌드 도출 + 연간 확정 스냅샷만 영속

| | |
|---|---|
| 상태 | **Accepted** |
| 작성 | James · 2026-09-01 |
| 의존 | Joshua D3·D4·§5.6 · SS-4·5·6·7 |

## 맥락

노미네이트 보드·연간 10선·월말정산은 전부 평론 메타데이터의 함수다 (D4 자동 도출 —
원 확인 Q2 대기 중이나 기본안). 리스트를 데이터로 관리하는 순간 "리스트 전 항목 =
평론 보유" 불변식이 사람 손에 의존하게 된다.

## 결정

1. **진행형 리스트(보드·진행형 10선·월말정산)는 매 빌드에 순수 함수로 재계산한다.**
   입력 = 평론·앨범·연도 설정. 저장물 없음. 증분 계산 없음(전량 재계산 — 수백 건 규모에서 최적화는 낭비).
2. **영속되는 유일한 리스트 = 연간 확정 스냅샷** `content/snapshots/<year>.md` (프론트매터 동결 + 본문 = 서문).
   원의 확정 선언 시 `finalize` 스크립트가 그 시점의 도출 결과를 **표시 필드까지 비정규화하여** 동결 저장 + 서문 md 결합 (SS-6).
   - 비정규화 이유: 이후 앨범 표기 수정·파일 이동이 스냅샷 표시를 바꾸면 "발표 시점의 선언"이 깨진다. 평론 링크(slug)만 살아 있는 참조로 남기고 SS-8이 매 빌드 검사한다.
   - 스냅샷 파일은 생성 후 수정 금지(관례 + 코드 리뷰). 확정 후 점수 수정은 평론 페이지에만 반영 (SS-6).
3. **연도 전환은 시계가 아니라 설정으로**: `config/site.yaml`의 `active_year`를 finalize가 올린다 (User 실행).
   홈 보드·진행형 10선은 `active_year` 기준. 스냅샷이 존재하는 연도의 `/list/{year}/`는 스냅샷만 렌더.
   → 빌드의 시계 의존을 월말정산의 "완결 월 판정" 1곳으로 최소화 (exceptions.md §결정성).

## 대안

1. **리스트를 데이터 파일로 관리** — 원 또는 User의 갱신 노동 + 점수와 어긋날 가능성(리스트 권위의 자해, D4 근거). 기각.
2. **확정 리스트도 매 빌드 재도출 + 잠금 플래그** — 앨범 표기 수정·삭제가 과거 발표물을 소급 변경. "발표 시점의 선언" 위반. 기각.

## 결과

- (+) USP-A 불변식이 구조적으로 보장되고 SS-8은 이중 안전장치가 된다.
- (+) 파생 로직이 순수 함수이므로 골든 테스트(같은 입력 → 같은 리스트)로 결정성을 회귀 검증.
- (−) 확정은 스크립트 실행이라는 명시적 행위가 필요 — 원의 "확정 선언 + 서문"이라는 편집 행위와 1:1 대응이므로 오히려 정합.
