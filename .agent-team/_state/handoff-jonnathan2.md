## 2. `genealogy-options.md`에 있고 `lineage-concepts`에 없는 것

1. **질문을 두 개로 쪼갬** — ① "최종적으로 어느 모습이 마음에 드나" ② "1차는 안 A로 시작해도 되나". 당신의 "A/B/C 중 뭐가 좋아?" 한 문장이 더 깔끔하지만, 원이 C를 고르고 지금 나오는 걸로 기대하는 사고를 ②가 차단한다. 리드도 "지금 고른 게 나중을 막지 않는다"는 말이 원의 결정 부담을 줄인다고 확인 — HTML 말미에 ② 취지 한 줄이 있으면 좋다.
2. **4행 비교표** (한눈에 보이는 정도 / 원이 추가로 할 일 / 만들 수 있는 때 / 글 몇 편부터 의미 있나) — 세 안을 다 본 뒤 되짚는 용도. HTML 마지막 화면에 넣을 만함.
3. **안 B의 SNS 연결점** — 흐름 그림을 "그대로 이미지로 저장해 인스타에 올릴 수 있는 모양"으로 만들고 글 공유 카드로도 쓸 수 있다는 점 (D8 유입 축 정합). 원의 언어로 B의 "좋은 점"에 추가하면 B의 매력이 실체를 얻는다.
4. 안 C의 아쉬운 점 표현 — *"지금 만들면 점 몇 개 찍힌 빈 지도라서, 오히려 사이트가 비어 보입니다"* — 당신 문서의 "초기 데이터 빈약"보다 원에게 와닿는 문장이라 생각.

## 3. tokens/components/handoff에서 흡수 후보 (근거 포함)

- **대비 계산표** — 토큰별 실측 대비를 표로 (내 tokens.md §1: ink 15.6:1 · ink-2 6.3:1 · ink-3 3.7:1→대형 전용 등). accessibility 증빙이 "AA 준수함" 선언이 아니라 수치가 된다.
- **공유 카드 점수 확정** — Joshua가 SS-15에서 "리스트 카드 점수 포함 여부"를 디자인에 위임. 내 판정: **리스트 카드는 순위만, 점수 숫자 비표시** (근거: D2 정신 — 점수를 피드의 간판으로 만들지 않음 + 피드에서 숫자는 논쟁 유발, 리스트 성격은 순위로 충분). 당신 §5는 "1~3위 요약"까지만 말하고 점수 여부 미확정 — 어느 쪽이든 명문 확정 필요. + **"평론 카드에 점수 없음"을 빌드 검사 항목으로** 추가 권장 (SS-15 AC 확장).
- **커버 법적 리스크 대비 순서** — 기본형(타이포만) 카드를 먼저 완성하면 SS-14 법적 결론이 불리해도 전 유형이 폴백으로 성립 (디자인이 James 결론을 기다리며 멈추지 않음).
- **이름 미확정 대비** — 워드마크를 텍스트 로고(세리프 700)로 잡으면 이름 확정 시 치환만.
- **이미지 계약** — 커버 산출 4단 (48~64/240~320/480/1200 카드용) · `width/height` 필수(CLS 0) · WebP+폴백 · 자체 호스팅 (SS-14).
- **폰트 계약** — 셀프 호스팅 서브셋 woff2 (KS X 1001 + Latin), 런타임 CDN 금지, `font-display:swap`. 내 선택은 Noto Serif KR 400/700 + Pretendard Variable — 당신 `--serif`/`--sans` 실값 미정이면 참고.
- **모션 전역 규칙** — 허용 목록제 (호버 색 전이 120ms · 카드 부상 · 이미지 페이드 200ms, 그 외 0) + `prefers-reduced-motion` 전이 0ms 전역 오버라이드.
- **지면×상태 집계 매트릭스 + QA용 접근성 체크리스트** — 내 design-handoff §4·§5 형식. Matthias(QA) 인수 기준으로 그대로 쓸 수 있는 모양.
