## 0. 원에게 전달하는 방법

`lineage-concepts.html`을 더블클릭해 열고, 스크롤하며 보게 한 뒤 **"A / B / C 중
뭐가 좋아?"** 한 문장만 물으면 된다. 파일 안에 각 안의 좋은 점·아쉬운 점·범위
표시(지금/곧/나중)가 원의 언어로 이미 들어 있다. 추가 설명 금지 —
설명이 필요하면 시안이 실패한 것이다.

**결정 부담 낮추기 (리드 지침):** 원이 선택을 어려워하는 패턴이 있으므로,
"지금 고른 것이 나중을 막지 않는다"는 문장을 시안 말미 강조 블록에 명시했다 —
유저 참여 결정 때 실제로 작동한 방식과 동일하다.

## 1. 세 안 요약

| | 안 A — 앨범 상자 | 안 B — 계보 블록 | 안 C — 계보 지도 |
|---|---|---|---|
| 형태 | 글 끝에 참조 앨범 자동 목록 | 글 속 "시작한 앨범 → 따라가는 앨범" 2단 카드 | 전용 페이지, 시간축 + 연결선 |
| 원의 추가 노동 | **0** (참조 목록은 이미 기획 확정) | 앨범당 역할 체크 1회 (시작/따라감) | 안 B와 동일 + 흐름 단위 관리 |
| 쓰는 데이터 | 참조 목록 (SS-9) | + `role?: "lead"\|"follow"` (James 확정 enum, 옵션 필드) | 안 B와 동일 |
| 몇 편부터 의미 있나 | 1편부터 | 1편부터 (lead 1 + follow 2면 성립) | 수십 편부터 — 그 전엔 빈 지도 |
| 범위 | **1차 확정** — Joshua Non-goals("데이터 층만")와 정확히 일치 | 1차 직후 저비용 확장 (HTML/CSS 블록 1개, JS 불요) | **보류** — USP-B 수요 실측 후 (usp.md §2) |
| 실패 비용 | 0 | 체크 안 하면 안 A로 자동 강등 (블록 미표시) | — |

**핵심 설계 판단: 세 안은 경쟁안이 아니라 같은 데이터 위의 성장 경로다.
A를 골라도 B·C가 막히지 않는다.** 같은 데이터 층(참조 목록 + 옵션 역할
태그) 위에 시각 층만 다르게 얹은 것이다. 이 사실을 시안 말미에 원의
언어로 명시했다 — "지금 고른 것이 나중을 막지 않습니다."

## 2. 각 안의 설계 근거

### 안 A — 글 끝 앨범 상자 (1차 확정형)
- US-4 AC1·AC2를 그대로 화면화: 평론 있는 참조 = 링크("평론 읽기 →"),
  없는 참조 = 플레인 상태("평론 준비 중"). 시안에 두 상태 모두 노출했다.
- 근거: Joshua Non-goals "계보 전용 시각화 UI(1차) 제외 — 데이터 층만".
  안 A는 시각화가 아니라 SS-9 링크 규칙의 지면 표현이므로 Non-goals에
  저촉되지 않는다.
- 주의: 안 A의 상자는 **시작/따라감을 나누지 않는다** (역할 태그는 안 B부터).
  원의 예시에서 DOPAMINE·HALF BLOOD는 "따라가는/시도하는" 쪽이다 —
  이를 시작(lead)으로 표기하지 않도록 시안 데이터를 검수했다.

### 안 B — 계보 블록 (원의 발화를 가장 직역한 형태)
- 원의 문장 *"선도한 앨범, 또는 현상에 따라가는 앨범을 나열해야 해요"* 의
  구조가 그대로 레이아웃이다: lead 1~2장(크게, seal 좌측 보더) → 화살표 →
  follow 카드 그리드 + "시도하는 아티스트" 한 줄. 지면 라벨은
  `시작한 앨범`/`따라가는 앨범` (enum 번역 — components.md §12b).
- role 태그 미입력 시 블록은 렌더되지 않고 안 A로 폴백 — 원의 표시를
  강제하지 않는다 (D7 정합).
- **SNS 파생 카드 (흡수 항목):** 이 블록은 빌드 타임에 이미지 한 장으로도
  뽑을 수 있다(OG 파이프라인과 동일 기술 — satori). charter §3 유입축 ③
  (원의 인스타)에 직결되는 부산물이라 시안의 "좋은 점"에 명시했다.
  단 구현 약속은 아님 — 원이 B를 고르면 James·리드와 범위 협의.
- 흐름이 다분기·다세대인 글에는 부적합함을 아쉬운 점에 명시했다.

### 안 C — 계보 지도 (미래형)
- 시간축(연도) × 흐름(행)의 정적 다이어그램. 실제 구현 시에도 빌드 타임
  SVG로 충분 — 클라이언트 JS 0 원칙 유지 가능.
- 단 1차 제외 사유(수요 미검증 + 초기 데이터 빈약)를 시안 안에서 원에게
  숨기지 않았다. "지금 만들 건 아니다"가 시안 문면에 있다.

## 3. 추천 (User Sovereignty — 결정은 원)

**A로 시작, 원이 역할 표시를 부담스러워하지 않으면 B.** C는 음악 이야기
10편 + 이동률 실측 후 재론 (usp.md §2 승계). 이 추천은 시안 말미에도
동일 문구로 있다 — 원이 다른 걸 골라도 그대로 따른다.

## 4. James 연동 확인 (2026-09-01 메시지 합의 → 아키 확정)

- `role?: "lead"|"follow"` 옵션 필드 확정 (api-contracts.md §4) — 안 B·C가
  소비, 안 A는 무시. "선도/추종"·"시작/따라감"은 지면 라벨 번역이다.
- 안 C의 라우트(`/lineage/{slug}/`)는 시안에만 존재. **1차 라우트 8종에
  추가하지 않는다** — 원이 C를 골라도 "나중에"로 안내 (시안에 명시됨).

## 5. 원 선택 후 처리

| 원의 선택 | 즉시 반영 | 이월 |
|---|---|---|
| A | ui-spec §음악 이야기의 앨범 상자 확정 (이미 반영돼 있음) | B·C 없음 |
| B | ui-spec에 계보 블록 컴포넌트 추가 (components.md §LineageBlock 예비 계약 있음) + SNS 파생 카드 범위 협의 | C 없음 |
| C | A 또는 B로 시작함을 안내 + C를 로드맵에 기록 | 실측 게이트 후 설계 착수 |
| 무응답/보류 | 안 A로 진행 (원 노동 0, 되돌릴 것 없음) | — |
